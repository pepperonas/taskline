# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

taskline is a Claude Code mod (function-hook plugin) that draws live progress of long-running jobs above the prompt. Repo `pepperonas/taskline`, local folder `~/claude/_mods/taskline` (it started as a statusLine script and was renamed — see docs/DESIGN.md, which also explains why it polls instead of watching and why it is a mod at all). English code and docs.

## Commands
```bash
npm install               # dev tools only (tsx, typescript, playwright)
npm test                  # node suite: tests/*.spec.ts, incl. drift guards (README ↔ code)
node --import tsx --test --test-name-pattern '<regex>' tests/layout.spec.ts   # single node test
claude plugin test .      # engine suite: hooks/*.test.tsx, run inside Claude Code's own host
python3 -m pytest tests   # python suite (python3 -m pytest tests -k <name> for one)
npm run typecheck         # tsconfig extends .claude-plugin/types/ (gitignored, generated by Claude Code); clean for hooks/, tests/*.spec.ts carry ~39 known errors
claude plugin validate .
npm run screenshots       # re-render docs/*.png from hooks/layout.ts
python3 demo.py --fast    # three simulated jobs through the real Python helper, to watch the band live
```
CI runs only the node suite (Node 20/22) and pytest (Python 3.8/3.12/3.13); the engine suite needs a local `claude`.

## Architecture
Data flow: jobs write `~/.claude/progress/<id>.json` (PROTOCOL.md, via `python/taskline.py` or `bin/taskline`) or are observed by watchers (`~/.claude/taskline/watchers.json`: filesize / logtail / dircount) → `register.tsx` polls once a second → tasks → phase + ETA → views → layout rows drawn in the `AbovePrompt` band.

- `hooks/register.tsx` — the only file with I/O (`$.fs`, `$.process`, `$.clock`). 250 ms tick, poll every 4th tick; re-reads a file only when mtime/size changed; pid liveness and cleanup every 5 s; `/taskline` command; snapshot/prefs live in `atom`s (module-level state is rebuilt on hot reload).
- Pure, unit-tested modules: `protocol.ts` (parse + `sanitize`; the file name is the task id, an `id` inside the file is ignored), `watchers.ts` (watcher config → tasks), `state.ts` (phase: running/stalled/aborted/done/error), `eta.ts` (time-weighted EMA sampled per `updated_at`, not per poll), `views.ts` (ordering, expiry, what to clean up), `layout.ts` (nine shrink levels, single vs. stacked, `+N more`), `format.ts` (cell widths incl. wide chars, bars, durations).
- The finish (`celebrate.ts`): `views.finished` spots running → done in `poll`; `register.tsx` queues it in the `celebration` atom, draws a terminal `Raster` above the task rows (one text line on desktop / no room / animation off) and repaints it with `$.ui.blit` at 30 fps. Frames are a pure function of time and seed, so tests and `tools/screenshots.ts` (PNG + GIF via ffmpeg) render any moment exactly. Judge visual changes on those renders, not on numbers.
- Shared types: `types/index.d.ts`. User settings: `userConfig` in `.claude-plugin/plugin.json`, parsed by `configOf` in register.tsx.
- Engine tests (`hooks/register.test.tsx`) fake fs, clock, env, store and processes beneath the plugin via `claude-code/testing`.

## Rules
- The version lives in seven places (plugin.json, package.json, marketplace.json, pyproject.toml, `__version__` in taskline.py, CHANGELOG, README badge + summary); `tests/docs.spec.ts` checks them all, plus the test-count badges, config table, `/taskline` subcommands, CLI commands, protocol and watcher fields. Change them together.
- Adding an optional protocol field does not bump `v`; it must be documented in PROTOCOL.md and read by the parser (drift guard).
- Every string from files or logs goes through `sanitize` (strips C0/C1 incl. ESC) and every row is clipped to `bodyColumns` — never let a file inject ANSI or wrap.
- Mutate every new test once and record it in docs/MUTATIONS.md. Run a mutant against the suite that is supposed to catch it; the replacement must match exactly once.
- No lockfile in the repo root (`.npmrc package-lock=false`): Claude Code would install the dev tools for every user.
- Plugin directory rules (its validator blocks otherwise): pass `$` only as a whole argument to top-level functions of the same file (no `read($, …)`/`update($, …)` from `claude-code`); write every call as `$.noun.method(…)` on one line, every `on('event', …)` on its own line; `$.state` keys as literals; never use `h` or `Fragment` as a name in a `.tsx` file (not even `typeof h`) — use `RenderNode`. Guarded in docs.spec. Every program the mod runs must be in the README privacy table (drift guard).
- Never put `options` on a `userConfig` field (the plugin directory refuses it); list choices in the description.
- Dev loading: symlink the repo into the session's `~/.claude/dev-mods/<session>/taskline` (hot reload), or `claude --plugin-dir .`. `install.sh` / `uninstall.sh` are for users (idempotent, record-based).
